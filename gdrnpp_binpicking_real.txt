gdrnpp bin picking real (반복 자동 집기 + UI)

* 스캐너는 한 프로세스만 연결할 수 있습니다. 노트북 커널이 카메라 서버(photoneo_server.py)를 잡고 있으면
  binpick_real.py가 시작할 때 그 서버를 끄고 넘겨받습니다. 돌리는 동안 노트북에서 촬영 셀은 실행하지 마세요.
  PhoXi Control 같은 다른 프로그램이 스캐너에 연결되어 있으면 먼저 연결을 끊으세요.
* 로봇 home 자세가 카메라 시야 밖이어야 합니다 (팔이 보이면 2D 확인에서 pick이 빠짐).

terminal 3  (촬영 -> 6D pose -> 집기 반복, UI 창)
cd ~/Projects/GDRNPP_bin_picking
.venv/bin/python binpick/binpick_real.py

  창이 뜨고 모델 로딩 + 카메라 연결(약 15 s)이 끝나면 [▶ 시작]을 누릅니다.
  3D 촬영 -> pose -> pick 최대 15개 (TOP_K) -> 한 개 집을 때마다 2D로 확인해 남은 pick 보정
  -> 남은 pick이 없으면 다시 3D 촬영 -> ... 를 [■ 정지]까지 반복합니다.
  잡을 부품이 없으면 --idle 초(기본 10 s)마다 다시 찍고, 부품을 채우면 이어서 집습니다.
  시작할 때, 3D/2D 촬영 전, 끝날 때 로봇이 home이 아니면 terminal 2에 /go_home을 요청합니다.
  terminal 2는 쉬고 있을 때만 받아들이므로 자기 home 이동(시작, 사이클 끝)과 겹치지 않습니다. 이미 home이면 보내지 않습니다.
  pick을 보내기 전에 terminal 1의 /compute_ik로 pre-grasp와 dive 자세를 terminal 2와 똑같이 풀어 봅니다.
  해가 없는 pick(예: 로봇 쪽으로 크게 기울어 손목이 닿지 않는 부품)은 보내지 않고 건너뜁니다 (UI "실패 / IK로 제외").
  (예전 terminal 3 matrix_calculator_fix, terminal 4 ee_6d.py는 필요 없습니다. 이 스크립트가 ee_6d.py로 target을 보냅니다.)


버튼
  ▶ 시작 / 재개
  ❚❚ 일시정지   지금 집는 사이클이 끝난 뒤 home(준비 자세)으로 가서 멈춤. 재개하면 2D로 한 번 확인하고 이어서 집음
  ↻ 다시 촬영   바로 home으로 감 (잡기 전이면 접근을 멈추고, 잡은 뒤면 놓고 감) -> 남은 pick을 버리고 3D로 다시 찍고 멈춤
                새 촬영 결과(이미지, pick 목록)를 보여주고 기다림. [▶ 재개]를 누르면 2D로 한 번 확인하고 새 pick으로 집음
                일시정지·대기(잡을 부품 없음)·정지 상태에서도 누르면 바로 촬영 (다시 누르면 또 찍음)
  ■ 정지        지금 사이클이 끝난 뒤 정지
  로봇을 바로 멈추려면 terminal 2에서 Ctrl+C


옵션
.venv/bin/python binpick/binpick_real.py --no-robot              # 로봇 없이 촬영, pose, pick 순서만 확인 (아무것도 안 보냄)
.venv/bin/python binpick/binpick_real.py --max-picks 20          # 20개 집으면 정지
.venv/bin/python binpick/binpick_real.py --idle 5                # 잡을 부품이 없을 때 다시 찍는 간격 (s)
.venv/bin/python binpick/binpick_real.py --autostart             # 로딩이 끝나면 바로 시작
.venv/bin/python binpick/binpick_real.py --no-ui --autostart     # 창 없이 터미널에서만 (Ctrl+C = 지금 사이클 뒤 정지)
.venv/bin/python binpick/binpick_real.py --offline data/pseudo_gt_70_bop 59 --no-robot   # 카메라 없이 저장된 프레임으로


결과 파일
runs/realtime/<시각>/            3D 촬영마다: picks.json, picks.csv, overlay.png, rgb.png, depth.npy, detections.json
runs/realtime/session_<시각>.csv  집기 한 번마다: 시각, pick, status(done/not started/failed), 사이클 s, 2D 보정 mm, TCP xyz
(--no-save 이면 저장 안 함)

설정 (binpick_real.py 위쪽 상수)
T_CAM_BASE (hand-eye), MAX_TILT, PICK_ORDER, TOP_K, TRACK_* (2D 보정), SAFE_* (로봇 안전 범위): 노트북과 같은 값
노트북과 다른 점 (bin 벽 규칙):
  노트북: 부품 중심에서 수평 10 cm 안에 벽이 있으면 제외 (BIN_WALL_MARGIN = 0.10)
          -> 가득 찬 bin에서 confident 부품의 절반 이상이 이것 하나로 빠짐 (부품과 같은 높이의 낮은 벽도 포함)
  binpick_real.py: 노트북과 같은 벽 거리 규칙(BIN_WALL_MARGIN = 0.08, 노트북 원래 0.10, auto_pick.py --wall-margin, 0 = 끔)에 더해
          실제 그리퍼 + 손목 카메라 모양(URDF 충돌 메시)을
          grasp 자세와 pre-grasp까지의 접근 구간에 놓고, 측정 점(bin 벽, 다른 부품)이 TOOL_HIT_MAX(30)개 넘게 들어오면 제외
          ("gripper hits bin wall" / "gripper hits parts").
          이웃 부품은 그리퍼 몸체가 PART_PUSH_MM(10 mm)까지 밀어도 됨 (bin 벽, 손목 카메라는 그대로 엄격).
          측정 노이즈(깊이가 튀는 작은 섬, SPECK_PX 150픽셀 미만)는 장애물로 보지 않음.
  툴 회전: 손가락이 둥근 구멍에 들어가므로 툴을 축 둘레로 돌려도 됨. 기울어진 부품은 RealSense 거치대(MOUNT_DEG = 180,
          툴이 똑바로 아래를 볼 때 로봇 쪽)와 케이블(CABLE_DEG = 90, 거치대에서 위에서 볼 때 반시계 90도)이
          둘 다 위쪽을 향하게 돌려서 hole 자세로 감. 거기서 닿으면 TOOL_YAWS(+-20, +-35도)만 더 돌려 봄.
          5도 미만으로 거의 똑바로 내려가는 부품은 돌리지 않음. 로그: "turned -64 deg about its axis (RealSense stand + cable up)"
  남은 제외 이유 중 "out of reach"(촬영당 약 15개)는 로봇 도달 거리 0.44 m 밖이라 bin을 로봇 쪽으로 옮겨야만 줄어듦.
